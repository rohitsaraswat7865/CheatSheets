Memory Model Deep Dive

STACK · HEAP · STATIC · BOXING
Stack Memory STACK

The stack is a LIFO (Last In, First Out) memory region allocated per-thread. Each method call pushes a stack frame containing local variables and parameters. When the method returns, the frame is popped — instant deallocation, no GC needed.

void Outer()
{
    int x = 10;           // pushed to stack frame
    Inner(x);            // new frame pushed on top
}                        // x's frame popped here

void Inner(int val)
{
    int y = val * 2;     // y in Inner's frame
    // Stack: [Outer: x=10] → [Inner: val=10, y=20]
}                        // Inner frame popped, y gone

// Recursion — each call = new frame
int Fib(int n) => n <= 1 ? n : Fib(n-1) + Fib(n-2);
// Fib(5): 5 nested frames → StackOverflowException
// if recursion is too deep (~1MB default stack)
Stack facts: ~1MB per thread (configurable). Extremely fast — just moves a stack pointer. No GC involvement. Value types on stack are cache-friendly (sequential memory).
Heap Memory HEAP

The managed heap is a large memory region managed by the Garbage Collector (GC). Objects are allocated here with new. The GC periodically identifies unreachable objects and reclaims their memory in generations (Gen0, Gen1, Gen2).

// Object allocation on heap
var list = new List<int>();   // heap: List object + int[]
list.Add(1);                   // int stored INSIDE the array

// Large Object Heap (LOH) — objects ≥ 85,000 bytes
var big = new byte[100_000];   // → LOH, rarely compacted

// GC Generations
// Gen0: new short-lived objects (~256KB)
// Gen1: survived one collection (~2MB)
// Gen2: long-lived objects (unlimited)

var cache = new Dictionary<string,object>();
// static field → GC root → cache stays in Gen2 forever
// until no more references reach it

// Force GC (testing only — never in prod!)
GC.Collect();
GC.WaitForPendingFinalizers();
Heap facts: Managed by GC. ~10x slower allocation than stack. Fragmentation possible. Gen0 collections are very fast (<1ms). Gen2 (full) collections can pause the app (but .NET 6+ has mostly background GC).
Boxing & Unboxing — Stack ↔ Heap Transitions
// BOXING: value type → object on heap
int x = 42;           // stack: 4 bytes
object o = x;         // heap: new int-wrapper object
// Stack: [x=42] [o=ref→0x1000]
// Heap:  0x1000 → { type-header | value=42 }

// UNBOXING: heap object → value type copy on stack
int y = (int)o;        // copies 42 from heap to stack
// y is a SEPARATE copy — mutating y doesn't change o

// HIDDEN boxing — common performance trap
ArrayList list = new();
list.Add(1);            // boxes int → avoid ArrayList!
list.Add(2);            // another allocation

// AVOID boxing: use generics
List<int> typed = new();
typed.Add(1);           // NO boxing — ints stored directly

// Interface boxing
IComparable ic = 42;   // boxes int!
// Fix: use generic constraints instead
T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) > 0 ? a : b;  // no boxing
Static Storage STATIC
// Static fields — live in "High Frequency Heap"
// (actually Type Object / Method Table in CLR)
// They are GC roots — never collected while type is loaded

class Config
{
    public static readonly string Version = "1.0";
    // "1.0" interned in string intern pool (static)

    public static int Count = 0;
    // int stored directly in Type Object — no GC

    public static List<string> Items = new();
    // reference stored statically → List on heap
    // List stays alive forever (static ref = GC root)
}

// String interning
string a = "hello";           // → intern pool
string b = "hello";           // same reference!
bool   r = object.ReferenceEquals(a, b); // true

string c = new string('h',1);  // forced new heap obj
string d = string.Intern(c);  // now same as "h" in pool

// Thread-static: one copy per thread
[ThreadStatic]
private static int _threadId;  // stack-like per thread
Memory leak risk: Static collections (List, Dictionary) that grow but are never cleared will cause memory leaks — they're GC roots so the GC can never collect them.

Value vs Reference Semantics

REF · OUT · IN · REF RETURNS
Passing by Value vs by Reference
// BY VALUE — a copy is made (default for structs)
void DoubleIt(int x) => x *= 2;   // x is a copy
int n = 5;
DoubleIt(n);                         // n is STILL 5

// BY REFERENCE — alias to same stack location
void DoubleRef(ref int x) => x *= 2;
DoubleRef(ref n);                    // n is NOW 10

// OUT — must assign before returning
bool TryParse(string s, out int result)
{
    result = 0;                       // must init
    return int.TryParse(s, out result);
}
TryParse("42", out var val);        // inline declaration

// IN — readonly reference (avoids copy, prevents mutation)
void Print(in Matrix4x4 m)          // 64-byte struct, no copy!
    => Console.WriteLine(m.M11);
// 'in' is ideal for large structs you only READ

// REF return — return reference to storage
ref int First(int[] arr) => ref arr[0];
ref var elem = ref First(arr);
elem = 99;    // modifies arr[0] directly!
Struct Design Guidelines
// GOOD struct: small, immutable, value-equal
readonly struct Money
{
    public decimal Amount { get; }
    public string  Currency { get; }
    public Money(decimal amount, string currency)
        => (Amount, Currency) = (amount, currency);
    public static Money operator +(Money a, Money b)
        => new(a.Amount + b.Amount, a.Currency);
}
// 'readonly struct' — compiler enforces immutability
// avoids defensive copies when passed 'in'

// BAD struct: mutable, large, has reference fields
struct BadIdea
{
    public List<int> Items;  // ref field in struct → confusion
    public string Name;       // 16+ fields → costly copies
    public void Mutate() { Name = "X"; }  // mutable = bugs
}

// ref struct — stack ONLY (cannot be on heap)
ref struct StackBuffer
{
    private Span<byte> _buf;
    public StackBuffer(Span<byte> buf) => _buf = buf;
    // Cannot: be boxed, implement interfaces (mostly),
    //         be async field, be in arrays, be a class field
}
Rule: Use structs when size ≤ 16 bytes, the type is logically immutable, and it won't be frequently boxed. Otherwise use a class.

Strings — Immutable, Interned, Heap-Allocated

STRING · SPAN · STRINGBUILDER · INTERPOLATION
String Internals
// string = sealed class, immutable, UTF-16 chars
// Layout: [object header][length][char0][char1]...

string s = "Hello";
// Heap: s → [TypePtr|SyncBlock|5|H|e|l|l|o]
// String literals → intern pool (static region)

// Immutability: every "modification" = new allocation
string a = "foo";
string b = a + "bar";  // new string on heap: "foobar"
// a still points to "foo" — a is unchanged

// Concatenation in loops = O(n²) — avoid!
var sb = new StringBuilder();      // single heap allocation
for (int i = 0; i < 1000; i++)
    sb.Append(i);                  // amortized O(n)
string result = sb.ToString();    // final allocation

// Zero-allocation: stackalloc + Span
Span<char> buf = stackalloc char[64];
int written = 42.TryFormat(buf, out int n) ? n : 0;
ReadOnlySpan<char> num = buf[..2];// slice — no allocation
String Formatting & C# 14 Patterns
// Interpolation — compiles to DefaultInterpolatedStringHandler
string name = "Alice";
int    age  = 30;
string msg  = $"Name: {name}, Age: {age:D3}";

// Raw string literals (C# 11+)
string json = """
    {
      "name": "Alice",
      "age": 30
    }
    """;
// No escaping needed — great for JSON/SQL/HTML

// UTF-8 literals (C# 11+) — zero allocation, static
ReadOnlySpan<byte> utf8 = "hello"u8;
// Lives in static data section — NO heap allocation!

// String comparison — always use Ordinal for performance
bool eq = string.Equals(a, b, StringComparison.OrdinalIgnoreCase);
int  cp = string.Compare(a, b, StringComparison.Ordinal);

// Span-based slicing — no copy, no allocation
ReadOnlySpan<char> full = "Hello, World!";
ReadOnlySpan<char> hello = full[..5];  // "Hello", no alloc
ReadOnlySpan<char> world = full[7..^1]; // "World"

// List<T> wraps a T[] with doubling growth strategy
var list = new List<int>();
// Heap: List object { _items=int[0], _size=0 }

list.Add(1);  // _items reallocated to int[4]
list.Add(2);
list.Add(3);
list.Add(4);
list.Add(5);  // triggers: new int[8], copy, old GC'd

// Pre-allocate to avoid copies
var presized = new List<int>(capacity: 1000);
// Heap: int[1000] allocated once, no reallocations

// CollectionsMarshal — unsafe but zero-copy span
Span<int> span = CollectionsMarshal.AsSpan(list);
// Direct access to backing array — no allocation
// DANGER: don't Add/Remove while holding this span!

// Struct lists stay on heap BUT inside contiguous array
// (no boxing since T is generic, not object)
var points = new List<Point>(); // Point[] — dense, fast
Dictionary<K,V> — Hash Table Internals
// Dictionary internals:
// int[] _buckets   — array of bucket indices
// Entry[] _entries — struct array {hash, next, key, value}
// All on the heap, but entries are value-type structs

var d = new Dictionary<string, int>();
d["a"] = 1;

// Lookup steps:
// 1. hash = "a".GetHashCode()
// 2. bucket = hash % _buckets.Length
// 3. walk chain via entry.next until key matches

// Collision handling — separate chaining (linked list in Entry)
// .NET uses open addressing from .NET 6+ (in some scenarios)

// Custom IEqualityComparer to avoid boxing
var fast = new Dictionary<int,string>(
    EqualityComparer<int>.Default);  // avoids IEquatable boxing

// GetOrAdd pattern
ref var val = ref CollectionsMarshal
    .GetValueRefOrAddDefault(d, "key", out bool exists);
if (!exists) val = 42;  // one lookup, not two!
Stack<T> and Queue<T>
// Stack<T> — LIFO, backed by T[] on heap
// (different from the call stack — this is a data structure)
var stack = new Stack<int>();
stack.Push(1);   // _array[0]=1, _size=1
stack.Push(2);   // _array[1]=2, _size=2
int top = stack.Peek();   // 2, no removal
int val = stack.Pop();    // 2, _size=1

// Queue<T> — FIFO, circular array on heap
var q = new Queue<string>();
q.Enqueue("A");  // head=0, tail=1
q.Enqueue("B");  // head=0, tail=2
string first = q.Dequeue(); // "A", head=1
// Circular: when tail wraps around, no reallocation needed

// PriorityQueue<T,TPriority> (.NET 6+) — binary heap
var pq = new PriorityQueue<string,int>();
pq.Enqueue("low",  3);
pq.Enqueue("high", 1);
pq.Enqueue("med",  2);
string next = pq.Dequeue(); // "high" (lowest priority int wins)
ArrayPool<T> — Rent, Use, Return
// ArrayPool avoids repeated heap allocations
// for temporary large arrays
using System.Buffers;

// Rent array from pool — may be LARGER than requested!
byte[] buffer = ArrayPool<byte>.Shared.Rent(1024);
try
{
    // Use buffer[0..1024] — ignore extra bytes
    var span = buffer.AsSpan(0, 1024);
    ProcessData(span);
}
finally
{
    ArrayPool<byte>.Shared.Return(buffer, clearArray: true);
    // clearArray=true: zero out before returning (security)
}

// Pool buckets (powers of 2): 16,32,64,128...1M+
// Requests over 1M → new array, not pooled
// Each thread has a TLS cache slot for speed

// Custom pool for domain objects
var pool = ObjectPool.Create<StringBuilder>(
    new StringBuilderPooledObjectPolicy());
Use ArrayPool when: you need temporary buffers (>1KB) in hot paths. Returns to pool keep Gen0 GC pressure low — critical for high-throughput APIs.

Generics & Constraints

TYPE PARAMS · CONSTRAINTS · COVARIANCE
Generic Types & Constraints
// Generic method — ONE JIT compile per value type T
// (class T reuse the same JIT code with object pointers)
T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;

// Constraints
where T : class           // ref type
where T : struct          // value type, non-nullable
where T : new()            // has parameterless ctor
where T : BaseClass        // inherits BaseClass
where T : IInterface       // implements interface
where T : notnull          // non-nullable (C# 8)
where T : unmanaged        // blittable, no refs (C# 7.3)
where T : allows ref struct// C# 13 anti-constraint

// Generic class — memory: one Type Object per T
class Repository<T> where T : class
{
    private readonly List<T> _store = new();
    public void Add(T item) => _store.Add(item);
    public T? Find(Func<T, bool> pred) => _store.FirstOrDefault(pred);
}
Covariance, Contravariance & Static Abstracts
// Covariance (out) — IEnumerable<Dog> IS-A IEnumerable<Animal>
interface IProducer<out T> { T Produce(); }
IProducer<string> strProd = null!;
IProducer<object> objProd = strProd;   // safe: string IS object

// Contravariance (in) — Action<Animal> IS-A Action<Dog>
interface IConsumer<in T> { void Consume(T item); }
IConsumer<object> objCon = null!;
IConsumer<string> strCon = objCon;    // safe

// Static abstract members (C# 11) — generic math!
interface IAddable<T>
{
    static abstract T operator +(T a, T b);
    static abstract T Zero { get; }
}
T Sum<T>(IEnumerable<T> src) where T : IAddable<T>
{
    T acc = T.Zero;
    foreach (var x in src) acc = acc + x;
    return acc;
}
// Used by System.Numerics.INumber<T> for generic math

Pattern Matching

SWITCH · WHEN · LIST · PROPERTY PATTERNS
All Pattern Types
object val = GetSomething();

var desc = val switch
{
    null                 => "null",           // null
    int i                => $"int: {i}",        // type
    int i and > 0        => "positive int",    // conjunction
    string { Length: 0 } => "empty string",    // property
    string s when s.StartsWith("A") => "A-string", // guard
    string s             => $"string: {s}",    // var
    Point { X: 0, Y: 0 } => "origin",         // positional
    Point(> 0, > 0)      => "Q1",              // deconstruct
    [.., 0]             => "ends in zero",   // list (C#11)
    [var first, ..]      => $"first={first}", // list slice
    not null             => "something",      // negation
    _                    => "default"          // discard
};

// Relational patterns
string Grade(int score) => score switch
{
    >= 90              => "A",
    >= 80 and < 90    => "B",
    >= 70              => "C",
    _                  => "F"
};
Pattern Matching in Conditions & is
// is pattern — inline type check + binding
if (animal is Dog { Name: "Rex" } dog)
    dog.Bark();

// Negation
if (animal is not Cat) HandleNonCat(animal);

// Multiple conditions
if (shape is Rectangle { Width: > 10, Height: > 5 } r)
    Console.WriteLine($"Big rect: {r.Area}");

// Switch statement with when guard
switch (request)
{
    case { Method: "GET", Path: var p } when p.StartsWith("/api"):
        HandleApi(p); break;
    case { Method: "POST" }:
        HandlePost(request); break;
}

// List patterns (C# 11)
int[] nums = { 1, 2, 3 };
if (nums is [1, .., 3]) Console.WriteLine("Starts 1, ends 3");
if (nums is [var a, var b, var c]) // exactly 3 elements
    Console.WriteLine($"{a},{b},{c}");  // 1,2,3

// Tuple patterns
string Traffic(bool on, bool fast) => (on, fast) switch
{
    (true,  true)  => "green",
    (true,  false) => "yellow",
    (false, _)     => "red"
};

Records

VALUE EQUALITY · IMMUTABILITY · WITH EXPRESSIONS
record class — Heap, Value Equality
// Concise positional record
record Person(string Name, int Age);
// Compiler generates:
//  - primary constructor
//  - init-only properties: Name, Age
//  - Equals() based on all properties
//  - GetHashCode() based on all properties
//  - ToString() → "Person { Name = Alice, Age = 30 }"
//  - Deconstruct(out Name, out Age)
//  - with-expression support via copy constructor

Person a = new("Alice", 30);
Person b = new("Alice", 30);
bool   eq = a == b;  // true — value equality!

// with expression — non-destructive mutation
Person older = a with { Age = 31 };
// Creates new Person("Alice", 31) on heap
// 'a' is unchanged — immutability preserved

// Inheritance
record Employee(string Name, int Age, string Dept)
    : Person(Name, Age);

// Additional members on records
record Point(double X, double Y)
{
    public double Distance => Math.Sqrt(X*X + Y*Y);
    public void Deconstruct(out double x, out double y)
        => (x, y) = (X, Y);
}
record struct — Stack, Value Semantics
// record struct = struct + value equality + with expression
record struct Color(byte R, byte G, byte B);
// Lives on STACK — no GC, cache friendly
// Mutable by default (unlike record class)

Color red   = new(255, 0, 0);
Color pink  = red with { G = 100 };  // stack copy
Color red2  = new(255, 0, 0);
bool  same  = red == red2;             // true

// readonly record struct — fully immutable
readonly record struct Measurement(double Value, string Unit);

// Choosing between record class vs record struct:
//
// record class:
//   - reference semantics (heap allocation)
//   - supports inheritance
//   - nullable reference type support
//   - use for domain entities, DTOs
//
// record struct:
//   - value semantics (stack allocation)
//   - no inheritance
//   - use for small immutable data (coordinates, measurements)
//   - ideal for return types avoiding heap alloc
//
// When to use neither:
//   - Mutable state → class or mutable struct
//   - Complex object graphs → class

Spans, Memory<T> & Zero-Allocation Patterns

SPAN · MEMORY · STACKALLOC · UNSAFE
Span<T> — Stack-Only View
// Span<T> is a ref struct — lives ONLY on stack
// It's a (pointer, length) pair pointing into:
//   - arrays (heap)
//   - stack memory (stackalloc)
//   - native memory
//   - string characters

// From array — no allocation, just a view
int[] arr  = { 1, 2, 3, 4, 5 };
Span<int> span  = arr;           // whole array
Span<int> slice = arr[1..4];      // [2,3,4] — no copy

// Stack allocation — purely on stack, zero GC pressure
Span<int> buf = stackalloc int[8]; // max ~256 bytes!
buf.Fill(0);
buf[0] = 42;

// Safe parsing without allocations
ReadOnlySpan<char> csv = "10,20,30";
while (csv.Length > 0)
{
    int comma = csv.IndexOf(',');
    var part = comma >= 0 ? csv[..comma] : csv;
    int.TryParse(part, out var num);
    Console.WriteLine(num);
    csv = comma >= 0 ? csv[(comma+1)..] : default;
}
// Zero string allocations in this entire loop!

// C# 14: implicit Span conversions (new!)
Span<int> s = [1, 2, 3];  // collection expression → stackalloc
Memory<T> — Heap-Compatible View
// Memory<T> = Span<T> but CAN be stored on heap
// Use when you need to pass slices across async boundaries

Memory<byte> mem = new byte[4096];
Memory<byte> seg = mem[..1024];      // no copy

// async — can use Memory (not Span) across await
async Task ReadAsync(Stream s, Memory<byte> buf)
{
    int n = await s.ReadAsync(buf);  // no allocation!
    Process(buf.Span[..n]);           // Span for sync ops
}

// MemoryPool — similar to ArrayPool but Memory-based
using IMemoryOwner<byte> owner
    = MemoryPool<byte>.Shared.Rent(1024);
Memory<byte> memory = owner.Memory;
// Automatically returned when owner is disposed

// Summary of Span vs Memory:
//  Span<T>   → fast, stack-only, use in sync code
//  Memory<T> → heap-storable, use across await
//  ReadOnlySpan / ReadOnlyMemory → for read-only access
C# 14 improvement: Implicit conversions between Span<T> and ReadOnlySpan<T>, and for collection expressions, are now first-class. This reduces boilerplate when passing spans to APIs.

Async / Await & Task Memory

TASK · VALUETASK · STATE MACHINE · THREADPOOL
How async/await Works Internally
// The compiler transforms async methods into a STATE MACHINE
// class (heap-allocated!) with captured local variables

async Task<int> FetchAsync(string url)
{
    int retries = 3;                   // captured in state machine
    var response = await _http.GetAsync(url); // suspension point
    // Thread returns to pool here ↑, resumes on any thread ↓
    return (int)response.StatusCode;
}
// Compiles to roughly:
// class FetchAsyncStateMachine {
//   int retries;              // local vars as fields (heap!)
//   string url;
//   HttpResponseMessage response;
//   int _state;
//   void MoveNext() { ... }
// }

// Task vs ValueTask — choose wisely!
// Task: always allocates on heap (~200 bytes)
async Task<int> GetFromCache()
{
    if (_cache.TryGetValue("k", out var v))
        return v;  // still allocates a Task wrapping the int
    return await FetchAsync("...");
}

// ValueTask: zero alloc when result is synchronous
async ValueTask<int> GetFromCacheV()
{
    if (_cache.TryGetValue("k", out var v))
        return v;  // NO heap allocation — value in struct
    return await FetchAsync("...");  // only allocs if truly async
}

// ConfigureAwait(false) — don't capture SynchronizationContext

    await Step2Async(ct);

    }

C# 14: Extension Members NEW IN 14

EXTENSION PROPERTIES · EXTENSION OPERATORS · STATIC EXTENSIONS
The New extension Block

C# 14 introduces a unified extension block syntax. Previously, only extension methods existed (static methods in static classes). Now you can also add extension properties, extension operators, and static extension members without modifying the original type.

Memory-wise: extension members add zero overhead to the extended type — they're syntactic sugar resolved at compile time. No additional heap allocation, no vtable entry.

// OLD way (C# 3+): extension method only
public static class StringExtensionsOld
{
    public static bool IsEmpty(this string s)
        => s.Length == 0;
}

// NEW way (C# 14): full extension block
public implicit extension StringExtensions for string
{
    // Extension PROPERTY (not possible before C# 14!)
    public bool IsEmpty => this.Length == 0;
    public bool HasContent => !string.IsNullOrWhiteSpace(this);
    public ReadOnlySpan<char> AsSpan => this.AsSpan();

    // Extension METHOD (same as before, cleaner syntax)
    public string Truncate(int max)
        => this.Length > max ? this[..max] + "…" : this;

    // Extension INDEXER
    public char this[Index i] => this[i];
}

// Usage — looks like native member!
string s = "Hello, World";
bool   e = s.IsEmpty;       // false
string t = s.Truncate(5); // "Hello…"
Static & Operator Extensions
// Static extension members — extend type itself, not instances
public implicit extension IntExtensions for int
{
    // Static extension method
    public static int Clamp(int val, int min, int max)
        => Math.Clamp(val, min, max);

    // Extension OPERATOR — adds operators to types you don't own!
    public static string operator *(string s, int n)
        => string.Concat(Enumerable.Repeat(s, n));
}

// Usage
string repeated = "ha" * 3;   // "hahaha"
int clamped = int.Clamp(150, 0, 100); // 100

// Extending a generic type
public implicit extension SpanExtensions<T> for Span<T>
    where T : INumber<T>
{
    public T Sum()
    {
        T total = T.Zero;
        foreach (var x in this) total += x;
        return total;
    }
}

// Explicit extension — requires explicit conversion
// (vs implicit: auto-applies to the type)
public explicit extension SafeList<T> for List<T>
{
    public T? SafeGet(int i)
        => i >= 0 && i < this.Count ? this[i] : default;
}
SafeList<int> safe = (SafeList<int>)myList; // explicit cast needed
Memory note: Extension members are zero-cost abstractions. They compile to regular static method calls — no vtable, no extra allocation, no performance penalty.

C# 14: The field Keyword NEW IN 14

AUTO-PROPERTY · BACKING FIELD · VALIDATION
field — Implicit Backing Field Access

The field keyword in C# 14 gives you access to a property's compiler-generated backing field inside a property accessor — without declaring an explicit field. This eliminates the common pattern of declaring a private field just to add validation logic.

In memory terms: the backing field lives wherever the containing type lives — on the stack (for structs) or the heap (for classes), as part of the object's layout.

// BEFORE C# 14: had to declare explicit backing field
class PersonOld
{
    private string _name = "";          // explicit backing field
    public string Name
    {
        get => _name;
        set => _name = value?.Trim()
            ?? throw new ArgumentNullException(nameof(value));
    }
}

// C# 14: use 'field' to access the synthesized backing field
class Person
{
    public string Name
    {
        get;
        set => field = value?.Trim()
            ?? throw new ArgumentNullException(nameof(value));
    } = "Unknown";               // initializer still works

    public int Age
    {
        get;
        set
        {
            if (value < 0 || value > 150)
                throw new ArgumentOutOfRangeException(nameof(value));
            field = value;       // 'field' = the hidden backing field
        }
    }
}

// Works in structs too — field on stack
struct Temperature
{
    public double Celsius
    {
        get;
        set => field = value >= -273.15
            ? value
            : throw new ArgumentException("Below absolute zero!");
    }
    public double Fahrenheit => Celsius * 9/5 + 32;
}

// (conceptually — actual IL varies)

// class Person in memory (heap object layout):
// [TypePtr: 8 bytes]

// [<Name>k__BackingField: string ref 8 bytes]  ← 'field'
// [<Age>k__BackingField:  int 4 bytes]         ← 'field'
// = 28 bytes per instance on heap

// Lazy initialization pattern with 'field'
class ExpensiveService
{
    public Connection Conn
    {
        get
        {
            if (field is null)
                field = new Connection("db");  // lazy init
            return field;

    }
}

Delegates, Lambdas & Events

Delegates & Closures — Memory Implications
// Delegate = strongly typed function pointer (heap object)
Func<int, int> square = x => x * x;
// Heap: delegate object { Target=null, Method=ptr }

// CLOSURE — captures local variable
// Compiler creates a display class on the HEAP
int multiplier = 3;                    // would be on stack...
Func<int, int> mult = x => x * multiplier;
// ...but 'multiplier' is LIFTED to heap:
// class <>c__DisplayClass0 { public int multiplier; }
// Heap: new <>c__DisplayClass0 { multiplier=3 }
// The lambda holds a reference to this display class

multiplier = 5;
var result = mult(4);  // 20! (sees updated value)

// Static lambda — NO closure, NO allocation
Func<int, int> pure = static x => x * x;
// Cached as a static delegate — single allocation at startup

// Multicast delegate
Action log = () => Console.Write("A");
log += () => Console.Write("B");  // invocation list on heap
log();  // prints "AB"
Events & Lambda Best Practices
// Events — publisher/subscriber pattern
class Button
{
    public event EventHandler<ClickArgs>? Clicked;

    protected virtual void OnClicked(ClickArgs e)
        => Clicked?.Invoke(this, e);  // thread-safe null check
}

var btn = new Button();
btn.Clicked += (s, e) => Console.WriteLine("Clicked!");

// Memory leak: if 'btn' is GC-rooted and handler references
// long-lived object, that object won't be collected!
// Always unsubscribe:
EventHandler<ClickArgs> handler = (s, e) => { };
btn.Clicked += handler;
btn.Clicked -= handler;  // explicit unsubscribe
// OR use WeakReference<T> for weak subscriptions

// C# 14: lambda parameter modifiers without types
Func<int, int> f = (ref x) => x++;  // NEW in C#14!
// Before, you had to write: (ref int x) => x++

Action<string> pr = (scoped s) => Console.Write(s);
// 'scoped' modifier without repeating the type

// Action<T>    → void return
// Func<T,R>   → returns R (last type param)
// Predicate<T> → Func<T, bool>
// Comparison<T>→ Func<T, T, int>

Unsafe Code & Pointers

Unsafe Pointer Operations
// Requires: <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
// and 'unsafe' keyword on method/block

unsafe
{
    // Pointer to stack variable
    int x = 42;
    int* ptr = &x;       // ptr = address of x on stack
    *ptr = 99;           // x is now 99

    // Pinned heap object — tell GC: don't move this!
    int[] arr = { 1, 2, 3 };
    fixed (int* p = arr)  // arr pinned during fixed block
    {
        for (int i = 0; i < 3; i++)
            Console.Write(p[i]);  // 123
    }  // arr unpinned — GC can move it again

    // Pointer arithmetic
    byte* buf = stackalloc byte[16];
    byte* end = buf + 16;
    for (byte* p = buf; p < end; p++)
        *p = 0xFF;

    // sizeof — compile-time struct size
    int size = sizeof(int);           // 4
    int ps   = sizeof(Point);         // depends on fields
}

Garbage Collector — How Objects Die

GEN0 · GEN1 · GEN2 · LOH · FINALIZE · IIDISPOSABLE
GC Lifecycle & Generations

The .NET GC is a generational, compacting, concurrent collector. Objects start in Gen0. If they survive a collection, they're promoted. Gen0 collects frequently (fast). Gen2 collects rarely (slow full GC).

// Object lifecycle:
// 1. new Foo() → allocated in Gen0
// 2. Gen0 full → collect: unreachable objects freed
// 3. Reachable objects → promoted to Gen1
// 4. Gen1 full → collect: survivors → Gen2
// 5. Gen2: long-lived objects (static, caches, singletons)

// Large Object Heap (≥85,000 bytes)
var big = new byte[100_000]; // → LOH, not compacted by default
// LOH fragmentation = performance problem
// Solution: ArrayPool<byte>.Shared.Rent()

// GC roots — objects that keep others alive:
// • Static fields
// • Local variables on active stack frames
// • CPU registers
// • GC handles (pinned objects, WeakReference targets)
// • Finalization queue

// Weak references — allow GC to collect
var weak = new WeakReference<MyObject>(new MyObject());
if (weak.TryGetTarget(out var obj))
    Use(obj);   // obj may have been collected!
// Useful for caches that should yield under memory pressure
IDisposable — Deterministic Cleanup
// Finalizer (destructor) — runs on GC thread, non-deterministic
// Use ONLY when owning unmanaged resources
class FileWrapper : IDisposable
{
    private IntPtr _handle;    // unmanaged resource
    private bool _disposed;

    public FileWrapper(string path)
        => _handle = OpenFile(path);

    public void Dispose()
    {
        Dispose(true);
        GC.SuppressFinalize(this);  // don't run finalizer
    }

    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;
        if (disposing)
        {
            // Free managed resources here
        }
        CloseHandle(_handle);   // free unmanaged
        _handle = IntPtr.Zero;
        _disposed = true;
    }

    ~FileWrapper()             // finalizer — safety net
        => Dispose(false);
}

// using — calls Dispose() at end of scope (even on exception)
using var file = new FileWrapper("data.txt");
// Equivalent to: try { ... } finally { file.Dispose(); }

// Modern: IAsyncDisposable
await using var conn = new AsyncConnection();
// Calls DisposeAsync() — use for async cleanup (sockets, streams)
Finalizer warning: Objects with finalizers are NOT collected on the first GC pass — they're placed on the finalization queue first, surviving an extra generation. This is why GC.SuppressFinalize is important when Dispose is called explicitly.
