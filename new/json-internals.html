JSON Internals — Parsing JSON in JavaScript

How JSON is parsed, serialised, validated, and optimised under the hood in JavaScript engines

A — JSON Format Fundamentals

  1. JSON Grammar & Data Types six value types: string, number, object, array, true/false, null — no undefined, no comments, no trailing commas, no single quotes
  2. JSON vs JavaScript Object Literal keys must be double-quoted strings, no computed keys, no methods, no Symbol keys, no Infinity/NaN/undefined values
  3. RFC 8259 & ECMA-404 canonical JSON specification, UTF-8 encoding requirement, duplicate key behaviour (last-value-wins vs implementation-defined), interoperability rules
  4. JSON Number Precision no distinction between integer/float, IEEE 754 double precision limits, Number.MAX_SAFE_INTEGER, large ID truncation, BigInt not serialisable
  5. Unicode & Escape Sequences in JSON \uXXXX escapes, surrogate pairs for characters above U+FFFF, \n/\t/\\/\", well-formed JSON strings (ES2019 fix for lone surrogates)
  6. JSON Superset Proposal (ES2019) U+2028 (Line Separator) and U+2029 (Paragraph Separator) now allowed in JS string literals, aligning JS with JSON grammar

B — JSON.parse Deep Dive

  1. Recursive Descent Parser how JSON.parse implements a top-down recursive descent parser internally, character-by-character scanning, state transitions for each value type
  2. Tokenisation / Lexing Stage scanner reads tokens ({, [, :, ,, strings, numbers, literals), whitespace skipping, error position tracking
  3. String Parsing & Escape Handling unescaping \", \\, \/, \b, \f, \n, \r, \t, \uXXXX, decoding surrogate pairs, invalid escape rejection
  4. Number Parsing sign handling, integer vs fraction vs exponent parts, leading zero rules, conversion to IEEE 754 double, precision loss detection
  5. The Reviver Function JSON.parse(text, reviver), bottom-up traversal order, key/value transformation, returning undefined to delete, this context inside reviver
  6. Reviver Use Cases date string → Date object, BigInt revival, Map/Set reconstruction, class instance hydration, custom type markers
  7. JSON.parse Error Handling SyntaxError on malformed input, error message quality varies by engine, position info, no partial parse — all or nothing
  8. Source Text Access (Stage 3 Proposal) JSON.parse with source — reviver receives raw source text, enabling lossless BigInt / high-precision number parsing without truncation
  9. Parsing Depth Limits deeply nested JSON can exceed stack, engine-specific recursion limits, stack overflow on crafted payloads, iterative parser alternatives

C — JSON.stringify Deep Dive

  1. Serialisation Algorithm recursive walk, toJSON() method called first if present, then replacer, then type-based serialisation rules, output assembly
  2. The Replacer Function JSON.stringify(value, replacer), top-down traversal, key filtering, value transformation, returning undefined omits the property
  3. Replacer as Array (Allowlist) passing string[] as replacer to whitelist keys, only applies to objects (not arrays), ordering preserved from allowlist
  4. The Space / Indentation Parameter third argument: number (indent spaces) or string (indent chars), max 10, pretty-printing, compact form when omitted
  5. toJSON() Protocol objects can define toJSON(key) to control their serialisation, Date.prototype.toJSON returns ISO string, custom class serialisation hooks
  6. Values That Get Dropped or Transformed undefined → omitted (object) / null (array), function → omitted, Symbol → omitted, NaN/Infinity → null, BigInt → TypeError
  7. Circular Reference Detection TypeError: Converting circular structure to JSON, internal visited set, manual cycle breaking, replacer-based cycle handling
  8. Well-Formed JSON.stringify (ES2019) lone surrogates output as \uD800-style escapes instead of malformed UTF-8, ensuring output is always valid Unicode

D — Engine-Level JSON Processing

  1. V8 JSON Parser Implementation dedicated C++ fast path (not generic JS parser), sequential scanner, direct object/array construction, avoids AST generation entirely
  2. JSON.parse Faster Than Object Literal parsing JSON string can be faster than parsing equivalent JS object literal — fewer grammar ambiguities, simpler token set, V8 optimisation
  3. Hidden Class / Shape Assignment on Parse V8 creates transition chains for parsed objects, same-shaped JSON → same hidden class, property order matters for shape reuse
  4. String Internalisation During Parse repeated keys get interned (same pointer), reduces memory for large arrays of similar objects, key interning cache
  5. Object Boilerplate Cloning V8 recognises repeated identical object shapes and clones a boilerplate instead of rebuilding, major speedup for API response arrays
  6. Memory Allocation During Parse heap allocation for every object/array/string, young generation pressure on large payloads, transient parse buffer, GC implications
  7. UTF-8 → UTF-16 Transcoding network data arrives as UTF-8, V8 strings are UTF-16, transcoding cost during parse, one-byte string optimisation for ASCII-only content

E — Streaming & Large JSON Handling

  1. Why Streaming Matters JSON.parse needs the complete string in memory, O(n) memory, blocks main thread, problematic for multi-MB payloads
  2. SAX-Style / Event-Based JSON Parsers emit events per token (startObject, key, value, endArray), constant memory, libraries: clarinet, jsonparse, oboe.js
  3. JSON Streaming over HTTP (fetch + ReadableStream) response.body.getReader(), chunked decoding with TextDecoder, incremental parse, progressive UI rendering
  4. NDJSON / JSON Lines newline-delimited JSON, one object per line, easy streaming parse with split('\n'), log ingestion, server-sent data
  5. JSON Pointer & Partial Extraction RFC 6901 JSON Pointer (/foo/0/bar), extract without full parse, JSONPath query expressions, selective field retrieval
  6. Web Worker JSON Parsing offload JSON.parse to a worker thread, postMessage serialisation overhead, Transferable optimisation, when it's worth the transfer cost
  7. Lazy / On-Demand Parsing parse only accessed fields, simdjson-inspired approaches, binary indexing over JSON text, trade-off: first-access latency vs full-parse cost

F — Schema, Validation & Type Safety

  1. JSON Schema declarative validation (type, properties, required, enum, pattern), draft versions (Draft-07, 2020-12), $ref for composition
  2. JSON Schema Validators in JS Ajv (compiled validation functions), json-schema, Zod schema → JSON Schema, validation speed: compiled vs interpreted
  3. Runtime Type Validation After Parse Zod, Valibot, io-ts, Superstruct — parse then validate, infer TypeScript types from runtime schemas, fail-fast vs collect-all-errors
  4. TypeScript & JSON.parse Typing JSON.parse returns any, type assertions vs runtime guards, generic wrapper patterns, unknown + narrowing, type-safe reviver
  5. API Response Contracts OpenAPI / Swagger JSON schema definitions, code-generated types, contract testing, response shape drift detection
  6. Discriminated Union Parsing type field as discriminator, parsing polymorphic JSON into correct class/type, Zod discriminatedUnion, tagged union patterns

G — Security Concerns

  1. eval()-Based Parsing (Legacy Danger) pre-JSON.parse era used eval('(' + text + ')'), arbitrary code execution risk, why JSON.parse is safe by design
  2. Prototype Pollution via JSON {"__proto__": {"admin": true}}, merge/assign spreading parsed objects, defence: Object.create(null), key filtering, libraries like lodash vulnerability history
  3. JSON Injection & XSS injecting </script> inside JSON embedded in HTML, <script>var data = {...}</script> escaping, Content-Type mismatch, XSSI prefix ()]}'\n)
  4. Denial of Service: Deeply Nested JSON stack overflow via [[[...]]] nesting, billion-laughs-style expansion, payload size limits, depth guards in custom parsers
  5. Denial of Service: Hash Flooding crafted keys causing hash collision O(n²), V8 mitigations (randomised hash seeds), payload key-count limits
  6. Sensitive Data Leakage in JSON.stringify accidentally serialising passwords, tokens, internal fields — replacer-based redaction, toJSON() exclusion, field stripping middleware
  7. Server-Side Request Forgery via JSON Input user-supplied URLs in JSON payloads, validating URL fields after parse, allowlist domains, never fetch user-controlled URLs blindly

H — Performance & Optimisation

  1. JSON.parse Performance Characteristics O(n) time, linear scan, string-heavy payloads slower (escape processing), V8 fast path for ASCII, cold vs warm parse
  2. JSON.stringify Performance O(n) walk, deep objects slower, replacer adds overhead, toJSON() call overhead, pre-computed JSON caching
  3. Fast JSON Libraries fast-json-stringify (schema-compiled serialiser), simdjson-js (SIMD-accelerated), fast-json-parse, JSON.parse vs hand-rolled parser benchmarks
  4. Schema-Based Serialisation (fast-json-stringify) pre-compile a stringify function from JSON schema, avoids type checking at runtime, 2-5× faster than native JSON.stringify
  5. SIMD JSON Parsing (simdjson) hardware-parallel character classification, structural index building, branchless parsing, JS bindings via N-API, gigabytes/sec throughput
  6. Avoiding Redundant Parse/Stringify Cycles caching parsed results, structuredClone vs parse/stringify for deep copy, pass-through JSON in middleware without re-serialise
  7. JSON Size Reduction short key names, array-of-arrays vs array-of-objects, gzip/brotli compression, JSON column-store format, eliminating nulls
  8. Benchmarking JSON Operations performance.now() around parse/stringify, realistic payload sizes, warm-up runs, V8 --trace-opt to check optimisation, profiling allocation

I — Serialisation Boundaries & Edge Cases

  1. Date Serialisation Date → ISO 8601 string via toJSON(), no automatic revival, reviver pattern: new Date(value), timezone pitfalls
  2. BigInt Serialisation JSON.stringify(1n) throws TypeError, solutions: toJSON() override, replacer with .toString(), reviver for revival, string-wrapped IDs
  3. Map, Set & Custom Collections Map/Set serialise as {}, manual conversion: [...map] → entries array, replacer/reviver codec pattern, custom toJSON
  4. RegExp, Error & Function Serialisation all serialise as {} or get dropped, manual source+flags for RegExp, error toJSON with message/stack, functions cannot round-trip
  5. Circular References & Object Identity JSON has no reference concept, cycles cause TypeError, $ref conventions (JSON Reference), flatted library for cycle-safe serialisation
  6. Sparse Arrays & Holes [1,,3] → [1,null,3] in stringify, holes become null, no way to represent array holes in JSON, dense array on parse
  7. undefined vs null vs Missing Key JSON has null but no undefined, undefined values omitted, missing key vs null key semantics, API contract implications
  8. Structured Clone vs JSON Round-Trip structuredClone handles Date, RegExp, Map, Set, ArrayBuffer, circular refs — JSON.parse(JSON.stringify(x)) loses all of these
  9. Property Enumeration Order JSON.stringify follows [[OwnPropertyKeys]] order (integer indexes → insertion-order strings), may differ from source JSON key order

J — Ecosystem, Formats & Tooling

  1. JSON5 superset: comments, trailing commas, unquoted keys, single-quoted strings, hex numbers, Infinity/NaN — config files (babel, vscode settings)
  2. JSONC (JSON with Comments) VS Code's tsconfig.json, // line and /* block */ comments, strip-json-comments, not a formal spec
  3. NDJSON / JSON Lines one JSON value per line, streamable, log aggregation, database dumps, ndjson npm package
  4. JSON Patch (RFC 6902) array of operations (add, remove, replace, move, copy, test), diff two JSON docs, apply patch, minimal update payloads
  5. JSON Merge Patch (RFC 7396) simpler alternative to JSON Patch, merge object with null = delete, no array operations, PATCH HTTP method
  6. MessagePack / CBOR / BSON binary JSON-like formats, smaller payloads, native binary/date types, JS libraries: msgpack-lite, cbor, bson — when to choose over JSON
  7. Protocol Buffers & JSON Comparison schema-first binary format, grpc-web, protobuf-to-JSON mapping, size/speed advantages, tradeoff: readability vs efficiency
  8. JSON in APIs: REST, GraphQL & tRPC REST default application/json, GraphQL response shape, tRPC serialisation layer (superjson), content negotiation headers
  9. superjson & devalue serialise Date, Map, Set, RegExp, BigInt, undefined through JSON, metadata sidecar approach, Next.js / SvelteKit integration
  10. JSON Diff & Visualisation Tools deep-diff, jsondiffpatch, visual tree diff, structural comparison, conflict resolution, merge strategies
