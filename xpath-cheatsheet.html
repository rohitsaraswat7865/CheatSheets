🛤️ Path Expressions paths
/rootRoot element

//cc anywhere in document

🏷️ Data Types types
node-setUnordered set of nodes
booleantrue or false
numberIEEE 754 double (NaN, Infinity valid)
stringSequence of Unicode characters
XPath 1.0 has only these 4 types. No integers, no dates, no null. Automatic coercion occurs in comparisons between node-sets and literals.
-- Numeric literals 42, 3.14, .5 -- String literals (single or double quotes) 'hello', "world" -- Node-set string value string(//title[1]) → text content of first title
📋 Common Patterns & Recipes patterns
-- Select all elements with a specific attribute value //*[@class='active'] -- Elements whose text contains a substring //p[contains(text(),'hello')] -- Nth child of a type //ul/li[3] -- Last child //ul/li[last()] -- All but first //ul/li[position() > 1] -- Even/odd rows //tr[position() mod 2 = 0] (even) //tr[position() mod 2 = 1] (odd) -- Parent of matching node //span[@id='x']/parent::* //span[@id='x']/.. -- Following sibling //h2[.='Intro']/following-sibling::p[1] -- Ancestor element //span/ancestor::div[@id='main'] -- Nodes that have a specific child //section[h2] -- Nodes that do NOT have a child //section[not(h2)] -- Attribute is one of multiple values //*[@type='text' or @type='email'] -- Elements with multiple class words (workaround — no contains-word in XPath 1.0) //*[contains(concat(' ',normalize-space(@class),' '),' btn ')] -- Count siblings //li[count(preceding-sibling::li) = 2] (third li) -- Select text nodes only //p/text() -- Self-closing / empty elements //*[not(*) and not(normalize-space(text()))] -- Deepest element matching name (//h1)[last()] -- Multiple conditions chained //product[@available='true'][price < 50][rating >= 4] -- Union of different paths //input | //textarea | //select
⚖️ Comparison Semantics gotchas

XPath comparisons between node-sets are existential:

-- True if ANY node in set equals 'x' //item[@val='x'] -- Comparing two node-sets: -- True if ANY node from A equals ANY node from B $a = $b -- Number comparison coerces string values: //price[. > 10] → string '15' compared as 15 -- String comparison uses Unicode code points: //name[. > 'M'] → lexicographic
⚠️ node-set = string checks if ANY node has that string value. Use count() and string() when you need exact set behavior.
🔬 Location Step Anatomy syntax
axis :: nodetest [ predicate ] [ predicate ] Examples: child::book[1] attribute::lang descendant-or-self::node() following-sibling::*[1] ancestor::div[@id] Full verbose path: /child::html/child::body /descendant::div[attribute::class='wrap'] /child::p[position()=1]
Every step evaluates relative to the context node established by the previous step.
📄 Document Order concepts

Axes in forward direction (document order):

child, descendant, descendant-or-self, following, following-sibling, self

Axes in reverse direction:

parent, ancestor, ancestor-or-self, preceding, preceding-sibling

position() and last() are sensitive to axis direction. In reverse axes, position(1) is the closest ancestor/sibling.
-- Nearest ancestor div: ancestor::div[1] -- Immediately preceding sibling: preceding-sibling::*[1]

-- Case-insensitive match (XPath 1.0 has no lower-case()) translate(@attr,'ABCDEFGHIJKLMNOPQRSTUVWXYZ', 'abcdefghijklmnopqrstuvwxyz') = 'hello' -- Class word boundary check contains( concat(' ', normalize-space(@class), ' '), ' myclass ' ) -- Select deepest element (no children) //*[not(*)] -- Select elements with exactly N children //*[count(*) = 3] -- Sum of attribute values across nodes sum(//item/@price) -- Count distinct values (no distinct in XPath 1.0 — workaround): count(//category[not(. = preceding::category)]) -- Get root element name name(/*) -- Select based on sibling content //li[following-sibling::li[.='End']]
